- This is the handover for `nixos-base/services/compose/`.
  - Snapshot
    - The source snapshot is dated 2026-11-07 on branch `arena/a7026f5a-my-nixos-base` at commit `66ded62` and was not build-tested.
    - This file was reshaped into nested bullets on 2026-11-07 (branch `arena/056af839-my-nixos-base`, commit `c103788`) without re-verifying its claims.

  - What this directory is for
    - It holds "compose-like" multi-component applications, meaning the things you would normally write a `docker-compose.yml` for expressed as NixOS modules.
    - Two different runtime styles live here side by side:
      - **NixOS containers** at `containers.<name>` use systemd-nspawn, share the host store and set `ephemeral = true`, and are used by `plausible-compose.nix` and `keycloak-compose.nix`.
      - **OCI containers** at `virtualisation.oci-containers` use podman with pinned image tags, and are used by `frappe-v16-compose/` and `n8n-compose.nix`.
    - `compose/default.nix` imports `./frappe-v16-compose`, `./hermes-agent-compose.nix`, `./keycloak-compose.nix`, `./n8n-compose.nix` and `./plausible-compose.nix`.
    - The same list carries `# ./unmaintained` marked as deliberately off.
    - `./unmaintained` holds chatwoot, wordpress and `compose-template.nix`, is **commented out**, and is documented in [`unmaintained/HANDOVER.md`](unmaintained/HANDOVER.md).

  - The shape every file follows
    - Declare `options.myOpt.<app>-compose = attrsOf (submodule ({name, ...}: { options = { enable; modules.*; … }; }))`.
    - Compute `enabled = filterAttrs (_: cfg: cfg.enable) config.myOpt.<app>-compose;`.
    - Wire into the primitives from `../`:
      - `myOpt.proxy-compose.<id>` provides the Caddy vhost, Cloudflare tunnel and sleep-on-idle instance.
      - `myOpt.sleep-on-idle.<id>` provides the health-check path and `endpoints.default`.
      - `myOpt.netns.<id>` gives the containers plus the proxy their own network namespace.
      - `myOpt.squid.<id>` provides the egress allowlist, so far only for frappe.
    - Put the actual units in `containers.<name>.config` or in `virtualisation.oci-containers.containers`.
    - Declare `sops.secrets."<name>/<purpose>"` for every env file or keybase file, never a value and only a path.
    - Set `autoStart = false` plus `set-cgroup-parent` so the whole stack is pulled up on first request and frozen afterwards.
    - The `modules` sub-attribute covering `modules.proxy-compose`, `modules.sleep-on-idle`, `modules.squid` and `modules.services.*` is **pass-through configuration from the host**.
      - The module usually merges its own defaults *after* it as `mkMerge [ cfg.modules.<x> { …defaults… } ]` so the host can override.
      - In a few places the order is `mkMerge [ …defaults… cfg.modules.<x> ]`, so check the order in the file you touch because it is not consistent.

  - File by file
    - `plausible-compose.nix` is a NixOS container and is well-formed.
      - It runs Plausible analytics as one nspawn container holding **plausible plus PostgreSQL plus ClickHouse**.
      - Its options are `plausible.{package,stateDir}`, `postgresql.{package,stateDir}` and `clickhouse.{package,stateDir}`.
      - `secretKeybaseFile-key` defaults to `<name>/secretKeybaseFile`.
      - `shared-run-secrets` is a read-only dir bind-mounted into the container and derived via `builtins.dirOf` from the sops secret path.
      - Notably it bind-mounts the **host** paths of `DynamicUser` services including `/var/lib/private/plausible` and asserts `systemd.services.plausible.serviceConfig.DynamicUser`, because bind-mounting at `/var/lib/plausible` would not work under `DynamicUser`.
      - The `tmpfiles` rules create all three state dirs with unspecified perms (`- - - - -`), so the services' own `StateDirectory` logic wins.
      - This file is the best template in the repo.
    - `keycloak-compose.nix` is a NixOS container.
      - It runs Keycloak plus PostgreSQL inside one container, published through a **unix socket** rather than a port.
      - The file is thin and delegates to `myOpt.keycloak.<name>` and `myOpt.postgresql.<name>`, only wiring the pieces together.
      - `myOpt.proxy-compose` takes `endpoints.default.origin.ip-socket = myOpt.keycloak.<name>.unix-socket`, so the Caddy, tunnel and sleep-on-idle chain lives in `../proxy-compose.nix`.
      - The proxyd itself is created by `../../keycloak.nix`, described in [`../HANDOVER.md`](../HANDOVER.md), which imports `../../../systemd-socket-proxyd.nix` *inside the container's config* and reads `localMode`/`hostname` from this file's `proxy-compose` entry.
      - `modules.keycloak`, `modules.postgresql` and `modules.proxy-compose` are pass-through.
    - `n8n-compose.nix` uses podman and is **WIP, so do not enable it blind**.
      - It declares a pinned `n8n.image`, two state dirs `~/.n8n` and `~/.n8n-files` with `tmpfiles 700 1000 1000`, `ports = ["host:port:port"]`, and a sleep-on-idle registration using `/healthz/readiness`.
      - **Known breakage (G6):** it reads `cfg.n8n.serviceName`, which is never declared, and `cfg.proxy-compose.hostname`, where the option is actually `modules.proxy-compose`.
      - It also looks up `config.myOpt.proxy-compose.${cfg.n8n.containerName}.cloudflared`, a key that `proxy-compose.nix` does not create because it keys by instance *name* rather than container name.
      - Evaluating an enabled n8n instance should therefore fail, so treat it as unfinished.
      - `myPkgs/oci-img.nix` already carries `n8n_v2 = 2.28.7` for when it is finished.
    - `hermes-agent-compose.nix` is a NixOS container and is a **skeleton**.
      - It declares a large option surface including `hermes-agent.{user,group,uid,gid,stateDir,port,unix-socket,settings,extra-users}`, `modules.{netns,sleep-on-idle,fastcrw,litellm,camofox,searxng}` and `telemetry`.
      - Its config is mostly **empty `mkMerge (mapAttrsToList (_: cfg: { }) enabled)` blocks**, so the plumbing for `myOpt.netns`, `myOpt.camofox`, `myOpt.litellm` and `sops.secrets` is stubbed.
      - What *is* implemented is users and groups, the `settings` **`apply`**, a two-endpoint sleep-on-idle instance and the container itself.
      - The `settings` apply is a `recursiveUpdate` that forces firecrawl backends, `browser.cloud_provider = "camofox"`, `model.base_url = ${myOpt.litellm.<name>.url}/v1`, telemetry toggles and `moa.presets.default.enabled = false`.
      - The sleep-on-idle instance maps `default` to the hermes socket and `litellm` to the LiteLLM socket.
      - **Additional breakage:** it references `outerCfg.myOpt.searxng.<name>`, but **no `myOpt.searxng` option exists anywhere in the repo** and the enabling code is commented out at line ~159.
      - `searxng` is also referenced in the container's `after`/`wants` list.
      - Anything that forces `optionalAttrs cfg.modules.searxng.enable …` while `enabled` fails, because `outerCfg.myOpt.searxng.${name}` is evaluated eagerly in the `let`.
      - It also uses `netnsCfg.path` and `.resolvConf`, which is **G1** again.
    - `frappe-v16-compose/` uses podman and is the largest thing in the repo, documented in [`frappe-v16-compose/HANDOVER.md`](frappe-v16-compose/HANDOVER.md).

  - Gotchas
    - **Two runtimes, one repo.**
      - A NixOS container shares `/nix/store` with the host and starts via `container@<name>.service`, while a podman container is a separate image and starts via `container-<name>-<service>.service`.
      - The primitives that enumerate units know this, since `set-cgroup-parent.nix` maps `"container@${nixos-con}"` versus `virtualisation.oci-containers.containers.<c>.serviceName` and `netns.nix` does the same, so if you add a new consumer of those lists, copy the mapping exactly.
    - **`config.containers.<name>.config` reads are self-referential.**
      - `plausible-compose.nix` reads `config.containers.${name}.config` *outside* the container to copy `services.postgresql.dataDir` and `services.clickhouse…StateDirectory` into bind mounts.
      - That works because NixOS modules are fixed-point, but it means the inner attr must be *declared* by the inner config or you get an infinite recursion or a missing attribute.
    - **`ephemeral = true`** is used everywhere, so the container's root filesystem is reset on every restart and *all* persistence must go through `bindMounts`.
      - Forgetting a bind mount silently loses data on restart rather than on first start.
    - **`nixpkgs.pkgs = pkgs`** must be set inside each container config as plausible does, otherwise nspawn containers re-evaluate a whole nixpkgs and the build explodes.
    - **`sops.secrets` path versus `builtins.dirOf`** matters because mounting a single secret file into a container is awkward, so the modules mount the *parent directory* read-only.
      - That directory also contains the age-key-derived plaintext of other secrets, so check `shared-run-secrets` before reusing it for a container you do not fully trust.
    - Nothing here sets `virtualisation.oci-containers.backend = "podman"` globally, and `frappe-compose.nix` and `camofox.nix` set it locally.

  - How to add an app
    - Copy `plausible-compose.nix` if the app is a NixOS package, which is fastest and shares the store, or `frappe-compose.nix` if it needs an upstream image.
    - Either way, declare `myOpt.<app>-compose`, wire `proxy-compose` plus `sleep-on-idle`, add state dirs via `tmpfiles`, pass secrets through sops, and set `autoStart = false` with `set-cgroup-parent`.
